# Script Parser

Читает `script.uploaded`, разбирает сценарий `.docx` (или `.txt`) и публикует `script.parsed`
(ТЗ 5.4): сцены сценария, реплики с ролью, ремарки отдельно, единый список ролей.

Как работает:
1. `docx_reader` извлекает непустые абзацы с оформлением: стиль, левый отступ, выравнивание,
   пустая строка перед абзацем; таблица «роль | реплика» превращается в «РОЛЬ: реплика» (FR-SP1).
2. Разметка абзацев: тип (`heading`, `character`, `dialogue`, `character_dialogue`,
   `parenthetical`, `action`, `transition`) и роль.
   - `SP_MODE=llm` — LLM через `llm-client` (FR-SP2, FR-SP6). Модель не пересказывает текст,
     а размечает пронумерованные абзацы, поэтому реплики остаются дословными, ответ короткий,
     а полноту легко проверить. Большой сценарий идёт чанками по `SP_CHUNK_CHARS` символов,
     известные роли и состояние на конце чанка передаются в следующий (FR-SP3). Ответ
     проверяется JSON-схемой и на полноту (метка на каждый абзац), при ошибке — повтор
     с текстом ошибки, затем `pipeline.failed` (FR-SP4). Версия промпта — `script-labels-v1`.
   - `SP_MODE=rules` — эвристики по типовой записи сценария, без LLM: для CI, офлайна и как
     база для сравнения качества с LLM.
3. Сборка (общая для обоих режимов): реплика — абзацы подряд после имени персонажа;
   ремарки в скобках внутри реплики отбрасываются; `line_id` = `p{номер абзаца}` — стабилен
   для того же документа (FR-SP5). Роли нормализуются: «ИВАН», «Иван», «ИВАН (за кадром)»,
   «ИВАН (ПРОД.)» → `ИВАН`; варианты написания уходят в `role_aliases`.

| Переменная | По умолчанию | |
|---|---|---|
| `SP_MODE` | `llm` | `llm` или `rules` |
| `SP_CHUNK_CHARS` | 6000 | размер чанка для LLM |
| `LLM_*` | | см. `libs/python/llm-client` |

Тестовый сценарий: `python tools/make_sample_script.py tools/sample_script.docx`.

Ограничения: имя персонажа, которое модель или эвристика записала по-разному («ИВАН» и
«ИВАН ПЕТРОВИЧ»), остаётся двумя ролями — склейку ролей пользователь делает в редакторе
(этап 4). Формат `.doc` и PDF не поддерживается.
